# PLANETARY GRID

행성 규모 에너지 기업 게임. 두 가지 모드가 있다.

- **간편 모드 (기본)** — 성장형 타이쿤. 지역 칸에 발전소(태양광 → 풍력 → 열발전 → 수력 → 핵분열 → 핵융합)를 짓고 레벨업해 수익을 키운다. 레벨 10·25·50·100…마다 출력 2배, 연구로 배수, 새 지역 열기, 수요 급증·부스트, 꺼 둔 동안의 오프라인 수익, 상장(명성 ★ 하나당 모든 수익 +10%)으로 재시작. 코드: `src/idle/core.ts`(규칙), `src/app/idle/app.ts`(화면).
- **상세 경영 모드** — 사업권·토지·계약·대출·송전망·고장까지 다루는 경영 시뮬레이션. 간편 모드 설정(⚙)이나 타이틀에서 전환한다. 아래 문서 대부분은 이 모드 설명이다.

- 기획 기준: `PLANETARY_GRID_Design_Baseline_1.0.md`, 결정 기록 `PLANETARY_GRID_Decision_Record_S05-S21.md`
- 기술: TypeScript 시뮬레이션 코어 + Three.js 화면, Windows 데스크톱 앱은 Tauri로 패키징

## 송도 플라이트 (별도 페이지)
인천국제공항에서 비행기로 이륙해 인천대교를 건너 송도국제도시 하늘을 날고, 내려서 걸어 다니는 3D 비행·산책 게임. **실제 지도 자료**로 만든 인천 일대(동서 40km × 남북 35km).
- 실행: `npm run dev` 후 **http://localhost:5173/songdo.html** (배포 빌드에서는 `dist/songdo.html`)
- 시작 화면에서 여객기·경비행기 이륙 / 센트럴파크 걷기 / 지도에서 고르기, 시간대(낮·노을·밤)
- 조작: 비행 `W`/`S` 추력, `↓`/`↑` 기수 들기/내리기, `←`/`→` 선회, `A`/`D` 방향타, `B` 브레이크, `G` 착륙장치, `F` 내리기(하늘에서는 낙하산) · 걷기 `WASD`, `Shift` 달리기, `Space` 점프 · 공통 `C` 시점, `M` 지도·순간이동, `N` 시간대, `R` 다시 시작, `H` 도움말. 터치 화면에서는 가상 조이스틱과 버튼이 뜬다.
- 담긴 것 (모두 실제 위치·모양):
  - 건물 약 12만 채의 실제 외곽선. 높이 정보가 있는 약 1만 4천 채(포스코타워-송도 305m, G타워 146m 등)는 실제 높이, 나머지는 건물 종류·면적·지역으로 추정
  - 도로·철도 5만여 개(고속도로·간선·이면도로·산책로), 다리 구간은 상판 높이와 교각, 인천대교는 실제 경로와 사장교 구간의 주탑 2개
  - 인천공항 활주로 4개(15L/33R·15R/33L·16L/34R·16R/34L, 번호·표지·등화), 유도로, 계류장, 탑승구 여객기
  - 실제 고도(산·언덕), 해안선, 호수·수로, 땅 쓰임새(공원·골프장·농경지·숲·주거지) 그림, 공원·숲·가로수 나무
  - 도로 위 자동차, 밤 창문 불빛·가로등·항공장애등
- 자료 출처: © OpenStreetMap 기여자(ODbL), Overture Maps Foundation, AWS Terrain Tiles(SRTM 등). 위성영상 추정 외곽선 중 공항 이동 구역 위의 것(주기 항공기 오탐)은 뺐다.
- 자료 다시 만들기: `tools/songdo-data/` — `python3 fetch.py <작업폴더>` (Overture·고도 타일 내려받기) → `python3 build.py <작업폴더> public/songdo` (지형 40m 격자·물 마스크 10m·건물·도로·나무·땅 그림 생성). 필요 패키지: pyarrow numpy pillow shapely scipy.
- 코드: `src/songdo/` — 자료 읽기 `data.ts`, 지형 `heightfield.ts`·`terrain.ts`, 건물 `buildings.ts`, 도로·다리 `roads.ts`, 인천대교 주탑 `bridge.ts`, 공항 `airport.ts`, 나무 `trees.ts`, 비행 역학 `aircraft.ts`, 걷기 `walker.ts`, 충돌 `world.ts`, 화면·입력 `main.ts`. 테스트 `tests/songdo.test.ts`.

## 실행

### 브라우저 (개발)
```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 시뮬레이션 테스트 (vitest)
npm run build      # 타입 검사 + 배포용 빌드 (dist/)
```
- 주소에 `?dev`를 붙이면 개발용 배속(60×, 600×)과 시작 파라미터가 열린다 (`src/app/main.ts` 참고).

### Windows 앱
- **자동 빌드**: 저장소에 push하면 GitHub Actions의 `Windows build` 워크플로가 설치 파일(NSIS `.exe`, `.msi`)을 만든다. Actions 실행 페이지의 Artifacts에서 내려받는다.
- **직접 빌드 (Windows PC)**: Node.js 22, Rust(stable), WebView2(Windows 10/11 기본 포함)를 설치한 뒤
  ```bash
  npm install
  npm run desktop:build   # src-tauri/target/release/bundle/ 에 설치 파일 생성
  npm run desktop:dev     # 개발 모드 창
  ```
- **주의 (cargo로 직접 빌드할 때)**: `npm run desktop:build`(= `tauri build`)를 쓰지 않고 `cargo build --release`만 하면 화면 파일이 exe에 들어가지 않아 `localhost` 연결 오류가 난다. 반드시 `--features tauri/custom-protocol`을 붙인다.
  ```bash
  npm run build && cd src-tauri && cargo build --release --target x86_64-pc-windows-gnu --features tauri/custom-protocol
  ```

## 첫 플레이 순서
처음 시작하면 **튜토리얼**이 화면 위쪽에 떠서 해당 버튼을 강조하며 안내한다 (지역 → 사업권 → 첫 발전소 → 배속 → 계약 → 첫 수익).
1. **새 게임**: 시나리오(빈손 창업 / 사업권 보유 / 소형 발전소 보유 / 사용자 지정), 난이도, 지도 크기(12·24·48·96개 지역)를 고른다.
2. **지역 선택** → **발전 사업권(소형)** 취득.
3. **소형 태양광(5일)** 또는 **소형 열발전(10일)** 건설. 부지는 자동 임대된다.
4. **계약** 화면에서 공급 여력 안의 **PPA**를 수락하면 수익이 안정된다.
5. 양쪽 지역에 **송전 사업권**을 얻고 이웃과 **송전선**을 이어, 시간대가 다른 지역의 저녁 피크에 판다.
6. 고장 전조(**점검 필요**)가 뜨면 예방 점검, 사업권·임대는 **자동화**로 갱신.

## 게임 시스템 요약
| 영역 | 내용 |
|---|---|
| 시간 | 고정 스텝 1분, 정산 15분, 게임년 120일(계절 30일). 배속은 스텝 수만 바꾼다 → 결정론 |
| 시장 | 가격 수용자(M4): 지역 수요와 기존 전력망 공급으로 가격 결정. 연속 가격 함수 + 부족 가산, 판매 한도 = 지역 수요 |
| 전력망 | 지역 허브 + 지역 간 송전선. 송전단 용량, 길이 비례 손실, 한 방향 흐름, 메리트 오더 배분 |
| 배분 순서 | 핵심 부하 → 계약 → 시장·저장 충전 → 잉여 저장 → 출력 제한 (같은 계층은 이행률 균등) |
| 시설 | 태양광·풍력·열발전·배터리·변전소, 소·중·대. 6단계 건설, 시운전 50% 출력 |
| 권리 | 발전·저장·송전·소매 사업권(120일, 유예 30일), 시설 부지 임대(갱신 +10%) 또는 매입(연 임대료 3배) |
| 계약 | PPA(지역 인도, 판매 한도 포함) · 직접 공급(고객 부하, 소매 사업권, 핵심 부하 가능). 위약금은 시장 전용이 이득이 되지 않게 설계 |
| 재무 | 원장(복식), 대출(원리금 균등), 지급불능 단계(경고 → 연체 → 구조조정 → 회생불능), 구제 옵션 |
| 사건 | 고장 전조 → 고장 → 자동 복구, 연료 가격, 수요 급변, 공급 충격(예고), 규제 변경(60일 전 통지) |
| 연구 | 13개 노드(발전·송전·저장·자동화·환경·건설), 최소 기간 있음. 발전 3단계 「핵분열 발전」이 핵분열 발전소를 해금 |
| 핵분열 발전 (후속 확장) | 기저 전원: 최소 출력 80%, 기동 6시간, 느린 램프, 저연료비, 건설 2배, 복구 2배, 폐기비 30% |
| 모듈 확장 (Q47) | 운영 중 시설에 모듈 최대 2개: 정격 +50%, 비용 55%, 공사 = 본 시설의 30%. 공사 중에도 기존 설비 운영 |
| 접속점 (S-08) | 지역 = 수요 허브(기본 접속점 80 MW) + 변전점(변전소마다). 새 시설은 여유 있는 접속점에 자동 연결. 변전점 고장은 그 변전점 시설만 정지 |
| 계획 건설 (Q32) | 여러 지역의 시설·송전선을 대기열에 담으면 자금·사업권·접속·동시 건설이 허락할 때 순서대로 자동 승인 |
| 긴급 복구 | 고장 난 시설·선로·허브의 남은 복구 기간을 절반으로 (복구비의 60% 추가, 고장당 1회). 핵심 부하 지역은 추천에 올라옴 |
| 긴급 경고 (S-21) | 핵심 부하 정전·대출 연체·사업권 정지·회생불능 → 경보음 + 자동 일시정지 (설정에서 끔) |
| 시설 실적 | 시설별 최근 30일 발전량·손익·가동률·이용률, 누적 순이익·건설비 회수율 |
| 저장 | 수동 3칸 + 자동 3칸(1·3·7일 간격, 가장 오래된 칸부터 덮어씀), 압축 보관, 파일 내보내기·가져오기 |
| 소리 | 외부 파일 없이 합성: 클릭·건설·준공·경고·경보음, 배경 앰비언트 |
| 자동화 | 추천 기본 + 정책별 자동 실행(갱신·점검·저장 조정), 예산·멱등·수동 고정 |
| 목표·기록 | 선택 목표 8개, 표준/사용자 지정 규칙 기록 분리 |

## 임시 요소와 한계
- 행성 지표·야간 불빛·시설 모형·효과음은 코드로 생성(디자이너 시안 색감 사용). 태양광·핵분열 카드는 임시 아이콘.
- 모든 수치는 [추후 밸런싱] 기준값. 자세한 확장 내용과 밸런스 점검 결과는 `docs/EXTENSIONS_1.1.md`.
- 영어 표시는 화면 문구를 사전으로 바꾸는 방식(beta)이라 일부 문장이 어색할 수 있다.
- AI 경쟁사(시장 M3)는 확정 결정(M4 가격 수용자 시장)과 충돌하므로 넣지 않았다.
