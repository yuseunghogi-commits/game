# PLANETARY GRID — 프로토타입 (P0)

행성 규모 에너지 기업 경영 시뮬레이션. 기획 문서는 `PLANETARY_GRID_Design_Baseline_1.0.md`와 `PLANETARY_GRID_Decision_Record_S05-S21.md`를 기준으로 한다.

## 실행
```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 시뮬레이션 테스트 (vitest)
npm run build      # 타입 검사 + 배포용 빌드 (dist/)
```
- `?dev`를 주소에 붙이면 개발용 배속(60×, 600×)이 열린다. 정식 배속은 1·2·4·8× (사용자 확정 Q1: 1× = 실시간 1초당 게임 1분).
- 조작: 지역 이름 클릭 → 오른쪽 패널에서 시설 종류·규모 선택 → **건설 승인**. 스페이스 = 일시정지, 숫자키 = 배속.
- 저장·불러오기는 브라우저 저장소(localStorage)를 쓴다.

## 구조
| 경로 | 내용 |
|---|---|
| `src/sim/` | 시뮬레이션 코어. DOM·렌더링 없음, 헤드리스 테스트 가능 |
| `src/world/terrain.ts` | 가상 행성 지형 (시뮬레이션과 화면이 같은 함수 사용) |
| `src/app/` | 화면: Three.js 행성, HUD |
| `tests/` | 불변식·결정론·저장 테스트 |
| `public/assets/` | 게임에 쓰는 가공된 이미지 |
| `assets/source/` | 디자이너가 보낸 원본 에셋과 검토 기록 |

## P0 범위
구현: 고정 스텝 시간(1분/15분 정산/1일), 6개 지역, 지역 수요(현지 시각 기준 일주기), M4 가격 수용자 시장(연속 가격 함수 + 부족 가산), 판매 한도 σ = 1.0, 열발전·태양광·풍력 3종 × 소·중·대, 6단계 건설(예약 → 단계별 청구, 시운전 50% 출력, 취소 환불), 원장(중복 방지 거래 ID), 저장·불러오기(버전·해시 검사), 결정론.

다음 단계: P1 지역 간 선로·손실·저장시설·정전 / P2 사업권·토지·대출·계약·자동화·연구 / Windows 패키징(Tauri).

## 임시 요소 (디자이너 에셋으로 교체 예정)
- 행성 지표: 코드로 생성한 가상 대륙 (디자이너 시안의 색감 사용). 시안 지도 파일을 받으면 교체 검토.
- 야간 불빛: 지역 위치에서 코드로 생성.
- 태양광 카드: 임시 아이콘 (원본 이미지 파일 미수신).
- 수치는 모두 [추후 밸런싱] 기준값.
