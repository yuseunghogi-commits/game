# 3D 사운드 (안드로이드)

유튜브·넷플릭스·브라우저·음악앱 등 **폰에서 나오는 소리를 헤드폰용 3D 입체 음향으로 바꿔 주는** 안드로이드 앱입니다.
루팅 없이 동작하며, 화면을 꺼도 백그라운드에서 계속 적용됩니다.

## 두 가지 모드

| | 강력 3D 모드 (추천) | 기본 모드 |
|---|---|---|
| 처리 방식 | 다른 앱 소리를 내부 캡처 → **앱이 직접 바이노럴 3D 계산** → 헤드폰 출력 | 폰 내장 `Virtualizer` 이펙트 사용 |
| 효과 | 확실함 (블루투스 포함, 폰 기종 무관) | 폰에 따라 약하거나 블루투스에서 거의 없음 |
| 요구 사항 | Android 10+, 처음 1번 권한 받기 (앱 안에서, Android 11+) | 없음 |
| 지연 | 약 20~100ms | 없음 |
| 미지원 앱 | 캡처를 막은 앱 (넷플릭스, 크롬, 스포티파이 등은 원음 그대로) | – |

### 강력 3D 모드 1회 설정 — 앱 하나로 (v2.0~, Android 11 이상)
PC 나 Shizuku 같은 다른 앱 없이, 앱 안에서 **무선 디버깅 페어링**으로 권한을 스스로 받습니다.

1. 앱 → **🔑 강력 모드 권한 받기**
2. (처음이면) 개발자 옵션 켜기: 설정 → 휴대전화 정보 → 소프트웨어 정보 → **빌드번호 7번 탭**
3. [시작] → 개발자 옵션이 열리면 **무선 디버깅** 켜기 → '무선 디버깅' 글자 눌러 들어가기 → **페어링 코드로 기기 페어링**
4. 6자리 숫자가 보이는 화면 그대로, 위에 뜨는 **'3D 사운드' 알림의 [코드 입력]** 에 6자리 입력 (안 보이면 상단바를 내리기)
5. '✅ 권한 받기 완료' 알림 → 끝. 이 과정 때문에 켠 무선 디버깅은 자동으로 다시 꺼집니다.

- Wi-Fi 에 연결돼 있어야 무선 디버깅을 켤 수 있습니다 (인터넷 안 되는 Wi-Fi 도 됨).
- 권한은 앱을 지우기 전까지 유지됩니다 (재부팅·업데이트해도 그대로).
- Android 10 이하이거나 잘 안 될 때: [다른 방법] → PC(USB + `adb shell pm grant com.spatialsound.app android.permission.DUMP`) 또는 이미 쓰는 Shizuku.

> 왜 필요한가요? 캡처해서 3D로 바꾼 소리를 내보낼 때 유튜브 **원래 소리를 꺼야** 소리가 두 번 안 들립니다.
> 다른 앱의 오디오 세션을 찾으려면 시스템 덤프 권한(DUMP)이 필요한데, 이 권한은 ADB(셸)로만 줄 수 있습니다.
> 앱이 폰 자신의 무선 디버깅(ADB)에 [libadb-android](https://github.com/MuntashirAkon/libadb-android) 로 접속해서
> `pm grant` 를 한 번 실행합니다 (페어링 키는 이 앱 전용, 앱 안에만 보관).
> (RootlessJamesDSP 와 같은 음소거 방식. 화면은 녹화하지 않고 소리만 가져옵니다.)

### 자동 업데이트 (v2.0~)
- 앱을 열면 6시간에 한 번 GitHub 의 최신 릴리스를 확인 → 새 버전이면 **[지금 업데이트]** → 받아서 설치 창 (설정·권한 유지)
- 처음 한 번은 '이 출처 허용'(출처를 알 수 없는 앱 설치)을 켜야 합니다. 받은 APK 는 앱 이름과 **서명 키**가 같은지 확인한 뒤 설치합니다.
- 화면 아래 **🔄 업데이트 확인** 으로 바로 확인, **새 버전 자동 확인** 으로 끄고 켜기.
- 서명 키: CI 가 항상 같은 키로 서명합니다. 저장소 비밀값 `APK_SIGNING_SECRET` 을 넣어 두면 그 값에서 같은 키를 만들어서
  영구히 유지되고, 없으면 Actions 캐시에 보관한 키를 씁니다 (7일 동안 안 쓰면 지워지므로 `keep-signing-key` 워크플로가
  주 2회 읽어 둠. 캐시는 `ccr-101057d7-9ssg5d` 브랜치와 기본 브랜치에서만 읽힘).
- 빌드·릴리스는 키를 **만들지 않습니다**. 키를 못 찾거나 APK 인증서가 지금까지 배포한 것(SHA-256 `069319a8…`)과 다르면
  릴리스가 멈춥니다 — 다른 키로 배포되면 설치된 앱이 업데이트를 못 받기 때문. 키를 잃었을 때만 `keep-signing-key` 를
  `create_if_missing` 으로 직접 실행하고 `release.yml` 의 `EXPECTED_CERT_SHA256` 을 바꿉니다 (사용자는 앱을 한 번 지우고 설치).
- 앱 버전(versionName·versionCode)은 저장소 맨 위 `RELEASE_VERSION` 에서 자동으로 (릴리스 태그와 항상 같게).

### 강력 3D 엔진 구성 (`BinauralProcessor.kt`)
1. **머리 모델 HRTF** (Brown & Duda 구조형 모델): 양 귀 시간차(구형 머리 8.75cm), 머리 그림자(소리 온 쪽 고음 +6dB / 반대쪽 최대 -20dB), 귓바퀴 반사(앞뒤 단서)
2. **가상 스피커**: 앞 L/R ±30°~±85° ("좌우 넓이"), 뒤 서라운드 ±110° (왼쪽 소리는 왼쪽 뒤에서만 → 좌우가 섞이지 않음)
3. **가상의 방**: 스피커마다 벽·바닥·천장 반사음 10개를 각자 도착 방향으로 HRTF 처리 ("방 울림")
4. **잔향**: 8채널 FDN, 방 크기별 RT60 0.4~2.4초 ("잔향" 선택)
5. 저음 보강 + 리미터

PC 측정값 (48kHz): 왼쪽에만 있는 소리의 좌우 귀 음량차 — 방 울림 없이 26~38dB, 큰 방 울림 포함 22~25dB. 처리 속도 실시간의 약 100배.
`demo/` 폴더에 처리 전/후 비교 음원이 있습니다 (헤드폰으로 들어 보세요).

## 3D 엔진 (강력 모드 / PC)
| 엔진 | 설명 |
|---|---|
| 🏠 **공간 모드 (실측 HRTF)** — 기본 | 실측 귀 특성 + **가상 스피커 7개**: 앞 L/R(±각도)·가운데(0°)·옆(±95°)·뒤(±각도). 주파수 성분마다 직접음/배경음과 가운데 성분을 분리해 보컬·대사는 가운데로, 박수·관중·울림은 옆/뒤로 보냄 |
| 🎯 **정위 모드** | 소리를 주파수 성분별로 분석해 스테레오 위치에 맞는 **정확한 방향**에 하나씩 배치(±"방향 펼침"°). 배경음(좌우 상관 낮은 성분)은 옆/뒤로 분리. 게임 발소리·영화 효과음 방향 파악용 |
| 기본 모드 | v1.1 까지의 계산 모델 엔진 |

PC 측정 (스테레오 위치 → 들리는 방향): 기존 엔진은 중간 위치가 ±10° 로 뭉쳤지만, 정위 모드는 30%·60%·100% 왼쪽이 각각 -40°·-70°·-90° 로 또렷하게 구분됩니다.

**🏠 가상의 방 (실측)**: 직육면체 방의 거울상 모델로 앞 스피커마다 1·2차 벽·바닥·천장 반사 48개(3.5~34ms, 중간 방)를
실제 기하로 계산하고, 반사음과 잔향을 45° 간격 8방향 버스로 모아 **방 전체를 실측 HRTF 로 렌더링**합니다.
잔향 꼬리의 두 귀 상관이 저음 0.66 / 중음 0.15 / 고음 0.16 으로 실제 방처럼 나옵니다 (이전 엔진 0.19 / 0.10 / 0.05).
음량은 방 크기와 관계없이 원음과 약 1dB 이내.

**🎵 선명도 — 배경음악이 뭉개지지 않게 (v1.8)**: 대사(정면) + 배경음악(드럼·베이스·화음·스테레오 잔향) 시험 음원으로
"리듬 보존"(대역별 세기 출렁임이 얼마나 남는지, STI 와 같은 방식 · 1 = 원음 그대로)을 재서 원인을 찾고 고쳤습니다.
| 원인 (측정) | 고친 방법 |
|---|---|
| 긴 잔향의 저음 꼬리가 킥·베이스를 뭉갬 (125Hz 대역 리듬 보존 0.50) | 잔향으로 보내는 소리에서 300Hz 아래를 뺌 (2단 고역통과) |
| 긴 잔향이 1~2kHz 를 흐림 (0.49) | 긴 잔향 양 60% 로 (초기 반사음은 그대로 → 머리 바깥 느낌 유지) |
| 가운데 소리가 가운데·앞 L/R 세 스피커에서 동시에 나와 귀에서 간섭 → 2kHz -6.7dB, 250Hz +2.5dB (탁한 소리) | 좌우가 완전히 같은 소리는 가운데 스피커로만. "가운데 스피커" 값은 얼마나 덜 같은 소리까지 가운데로 모을지 |
| 원음을 섞는 3D 강도 85% 가 HRTF 지연(0.5~1.4ms)과 어긋나 빗살 간섭 | 프리셋 3D 강도 100% (보컬 85%) |

결과 (음악 프리셋): 리듬 보존 0.71 → 0.84, 가운데 소리 대역 요철 3.0 → 1.3dB, 배경음악/대사 균형 -1.1 → -0.7dB (0 = 원음과 같음),
두 귀 상관(넓은 느낌) 0.10 → 0.12 로 공간감은 그대로. 영화관 프리셋 리듬 보존 0.59 → 0.79.

**🔉 저음 (v1.10)**: 200Hz 아래는 가상 스피커를 거치지 않고 L → 왼쪽 귀, R → 오른쪽 귀로 바로 (100Hz 아래 전부, 200Hz 까지 서서히).
| 문제 (측정) | 원인 | 고친 방법 |
|---|---|---|
| 좌우로 넓게 퍼진 저음이 3~4dB 작음 | 모노 저음은 두 가상 스피커 소리가 귀에서 겹쳐 커지는데 넓은 저음은 안 겹침 | 저음 직통 |
| 저음 보강을 올릴수록 깊은 저음이 깎임 (음악 50Hz -8.6dB, 영화관 -12dB) | 측정 HRTF 는 깊은 저음에서 위상이 거의 반대(+150°)인데 보강은 원음에 따로 더함 → 상쇄 | 보강을 렌더러 안에서 0위상 곡선으로 |
| 방 반사음이 낮은 저음을 상쇄 (50Hz -7dB) | 3~10ms 반사음들이 저음에서 서로 간섭 | 방 소리도 저음 직통 구간에서 뺌 |
직통 저음에는 정면 HRTF 의 위상만 입혀서 HRTF 를 거친 소리와 이어 붙임 (단순 지연으로 맞추면 160Hz 에서 -7.5dB 상쇄).
결과: 저음 보강 0 일 때 50~200Hz 가 모노·넓은 저음 모두 원음 ±1dB (넓은 저음 125Hz -3.6 → -0.1dB), 음악 프리셋(보강 25%)은
50~125Hz 가 매끈하게 +2dB. 배경음악 리듬 보존 0.84 → 0.88 (영화관 0.79 → 0.84).

**👂 귀 맞춤**: 사람마다 귀 모양이 달라 앞/뒤가 헷갈릴 수 있어서, 실측 데이터를 머리·귀 크기 5단계로 늘이거나 줄여 고를 수 있습니다 (주파수 스케일링). "귀 맞춤 테스트"에서 앞→뒤 소리를 들어 보고 가장 확실한 단계를 고르세요.

### ⬆️ 높이 (위아래) — 실측 엔진
| 기능 | 설명 | 헤드폰(Bose 등) |
|---|---|---|
| **앞 스피커 높이** | 앞·가운데 가상 스피커를 귀 높이에서 -20°~+40° 로 (영상 화면 높이에 맞추기) | ✅ |
| **천장 스피커 4개** | 배경음 일부를 머리 위쪽 가상 스피커로: 앞 2개(기본 ±45°, 위 45°) + 뒤 2개(±135°, 위 45°) — 7.1.4 배치 | ✅ |
| **바닥 스피커 2개** | 배경음 일부를 아래쪽에서 (기본 ±45°, 아래 30°) → 위·아래·옆·뒤 전부 감싸는 소리 | ✅ |
| **위치 조절** | 배치도에서 ▲/▼를 끌어 옮기기: 돌리면 방향, 머리 쪽으로 끌면 더 높이, 실선 원(귀 높이) 바깥으로 끌면 아래 (천장 30°~85°, 바닥 -10°~-40°). 슬라이더로도 조절 | ✅ |
| **위아래 헤드 트래킹** | 갤럭시 버즈 센서의 위아래 각도까지 반영 → 고개를 숙여도 소리가 제자리 | 버즈만 |

방식: 수평면은 기존 실측 데이터(2° 간격)를 그대로 쓰고, **MIT KEMAR**(높이 -40°~+90°, 368 방향)에서
"같은 좌우 각도의 수평 방향 대비, 위/아래에서 올 때 달라지는 주파수 모양"만 가져와 곱합니다(±6dB, 1옥타브 평활 — 귀마다 다른 좁은 골짜기는 버리고 넓은 경향만 써서 보컬 음색이 변하지 않게).
위로 올라간 옆 소리는 좌우 시간차가 줄어드는 것도 반영 (왼쪽 90°·위 45° → 354µs = 왼쪽 45° 수평과 같음, PC 측정).
높이 기능을 끄면 이전 버전과 출력이 같습니다(차이 1e-7, 부동소수점 반올림 수준).
배경음 나누기: 앞 (1−r)(1−h)(1−b), 옆·뒤 r(1−h)(1−b), 천장 h(1−b) (앞·뒤 쌍에 반씩), 바닥 b — 바닥 0% 이고 3D 강조 0% 이면 천장이 한 쌍이던 계산과 구조가 같고,
천장·바닥·강조를 모두 끄면 v1.6 과 출력이 완전히 같습니다(차이 0). 각 복사본은 서로 다른 지연(옆 4ms·천장 앞 6ms·뒤 9ms·천장 뒤 10.5ms·바닥 2.5ms)으로 디코릴레이션.
한계: 스테레오 원음에는 높이 정보가 없고, 위아래 지각은 귀 모양 개인차가 커서 사람에 따라 "위"보다 "넓고 열린 느낌"으로 들릴 수 있습니다.

### ✨ 3D 강조 — 실측 엔진
남의 귀(KEMAR)로 측정한 데이터는 내 귀와 달라서 앞/뒤·위/아래 단서가 약하게 들립니다. 3D 강조는 이 단서를 키웁니다:
- 같은 좌우 각도의 앞/뒤 짝 방향(θ ↔ 180°−θ)과 비교한 주파수 모양 차이(1/2 옥타브 평활)를 (α−1)배 더 벌림 (α = 1 + 강조%)
- **뒤쪽 방향이 차이의 3/4, 앞쪽이 1/4** 을 맡아서 앞(보컬) 음색은 거의 그대로, 뒤는 더 뒤처럼
- 700Hz 아래는 그대로(1.4kHz 까지 서서히), 최대 ±10dB, 0위상(시간차 그대로) / 위·아래 단서도 α배 (최대 ±9dB)

PC 측정 (왼쪽 45° 앞 vs 135° 뒤, 가까운 귀 4kHz 대역): 앞뒤 차이 9.5dB → 강조 30%(기본) 12.3dB → 100% 18.9dB.
정면(보컬) 음색 변화는 30% 에서 최대 +0.7dB (12kHz), 100% 에서 +2.3dB.
비슷한 원리의 연구: D. Brungart, G. Romigh (2009) "Spectral HRTF enhancement for improved vertical-polar auditory localization" (WASPAA) —
KEMAR 같은 남의 귀 데이터에서 위·앞뒤 오차를 크게 줄였다고 보고. 이 연구의 방법은 미국 특허(US 8,428,269)로도 등록돼 있어, 개인 사용이 아니라 판매용으로 쓰려면 따로 확인이 필요합니다.
데이터: MIT KEMAR HRTF (W. Gardner, K. Martin, MIT Media Lab, 1994) 확산음장 등화 compact 세트 —
[mit-hrtf-lib](https://github.com/jhonmark/mit-hrtf-lib) (MIT License) 배열에서 추출 (`tools/export_mit_elev.py`).

### 🧭 헤드 트래킹 (고개를 돌려도 소리가 제자리에)
강력 3D 모드에서 머리 센서가 있는 이어폰을 고르면, 고개를 돌린 만큼 가상 스피커·반사음을 반대로 돌려
소리가 공간에 고정됩니다 (앞/뒤 구분과 머리 바깥 느낌이 크게 좋아짐).
| 장치 | 방식 |
|---|---|
| **갤럭시 버즈** (Buds+ 이후: Buds Pro·Buds2·Buds2 Pro·Buds3 계열) | 버즈의 360 오디오용 센서를 블루투스(RFCOMM, 삼성 관리 서비스)로 직접 읽음. 약 50회/초 쿼터니언 → 좌우 회전각 |
| **이어폰 표준 머리 센서** (Android 13+) | Android 표준 `TYPE_HEAD_TRACKER` 를 공개하는 이어폰 (픽셀 버즈 프로 등) |

갤럭시 버즈 프로토콜·각도 계산 참고 (MIT): [BudsPro-Headtracking](https://github.com/timschneeb/BudsPro-Headtracking) ·
[GalaxyBudsClient](https://github.com/timschneeb/GalaxyBudsClient) (Tim Schneeberger),
[galaxy-buds-headtracker](https://github.com/AkbulutMirac/galaxy-buds-headtracker) (AkbulutMirac).
PC 검증: 보내는 프레임이 표준 CRC-16/XMODEM 계산과 바이트 단위로 일치, 귀에 0~60° 기울여 꽂은 경우에도
좌우 회전은 정확히(±0.0°), 끄덕임은 좌우로 새지 않음(0.00°). 실제 버즈 연결은 기기에서 확인 필요.
헤드폰(Bose QC 등)은 머리 센서가 없어 지원되지 않습니다.

### 🎧 헤드폰 보정
3D 음향은 평평한 헤드폰을 가정하는데 실제 헤드폰은 모델마다 고유 음색(특히 2~10kHz 의 좁은 봉우리/골짜기)이 있어
방향 단서를 흐립니다. 쓰는 헤드폰을 고르면 측정 데이터 기반 보정 EQ(바이쿼드 10개)를 마지막 단계에 겁니다.
수록: Bose QuietComfort Headphones(2023)·QC Ultra·QC45·QC35 II, Sony WH-1000XM5/XM4·WF-1000XM5,
Apple AirPods Max·Pro 2·4, Samsung Galaxy Buds3 Pro·Buds2 Pro·Buds FE.
데이터: [AutoEq](https://github.com/jaakkopasanen/AutoEq) (Jaakko Pasanen, MIT License) 결과 —
측정 출처 Rtings, oratory1990, HypetheSonics (`tools/build_hp_eq.py`).
AutoEq 의 프리앰프(부스트로 깨지지 않게 미리 낮춘 볼륨, 모델별 -1.9~-6.4dB)는 최대 3.5dB 까지 되돌려서 3D 를 켜도 원음과 같은 크기로
들리게 합니다 (Bose QC 2023: -3.6dB → -0.3dB). 최고점 -1dBFS 로 마스터링된 음원에서도 처리 후 최고점은 -0.9dBFS 이고,
넘는 순간은 끝단 리미터가 잡습니다 (측정상 리미터로 잃는 음량 0.0dB, 리듬 보존 변화 없음).

## 동작 원리

- **모든 앱에 적용 (기본)**: 효과를 오디오 세션 0(기기 전체 출력 믹스)에 붙입니다.
  유튜브처럼 오디오 세션을 공개하지 않는 앱에도 적용되는 유일한 비루팅 방법입니다.
- **앱별 세션**: 스포티파이·삼성뮤직·Poweramp 등은 재생 시 오디오 세션을 방송(broadcast)하는데,
  이를 받아 해당 세션에도 효과(특히 잔향)를 붙입니다. 전체 출력에 이미 3D가 걸려 있으면
  이중 처리를 막기 위해 앱별 세션에는 잔향만 추가합니다.
- 다른 이퀄라이저 앱이 제어권을 가져가면 5초마다 확인해서 다시 연결합니다.

## 주의 / 한계

- 요구 사항: **Android 8.0 (API 26) 이상**
- 세션 0 전체 효과는 안드로이드에서 공식적으로 *deprecated* 상태라 **일부 기기(제조사 펌웨어)에서는 막혀 있을 수 있습니다.**

## 👂 좌우 대칭 (v2.4)
측정 HRIR(KEMAR)은 두 귀가 완전히 같지 않아서 (왼쪽 귀 θ vs 오른쪽 귀 −θ: 정면 6.3kHz -3.1dB, 90° 10kHz -4.6dB·16kHz -4.2dB,
250~500Hz -0.7dB, 정면 두 귀 시간차 -12.9µs) 같은 소리가 왼쪽에서 더 먹먹하게 들렸습니다.
`HrtfRenderer.symmetrize`: 짝마다 크기 차이(dB)를 1/6옥타브 평활해 반씩 나눠 맞추고, 정면 ±20° 에서 잰 시간 치우침을
두 귀에 반씩 선형 위상으로 되돌림 → 엔진 출력 가운데 소리 좌우 차이 최대 0.3dB, 두 귀 시간차 -0.1µs.

## 🎚 음색 (v2.1 → v2.3 음색 보정 슬라이더)
원음과 비교했을 때 "필터 낀 듯한" 소리의 원인은 두 가지였습니다 (측정: 분홍잡음, 1/6옥타브, 1kHz 기준).
1. 측정용 더미헤드(KEMAR) 귀 모양: 정면 소리가 3~5kHz +3~5dB, 6~8kHz -4~6dB
2. 헤드폰 보정을 측정대로 100% 적용: Bose QC 2023 은 6.3kHz 좁은 홈 -5.7dB 가 1번과 겹쳐 -9dB 구멍, 저음 -4.6dB

| Bose 보정 켬 | 가운데(대사·노래) 최대 굴곡 | 가운데 평균 | 넓은 소리 평균 | 배경음악-대사 |
|---|---|---|---|---|
| v2.0 | -9.2dB (6.3kHz) | 5.2dB | 2.7dB | -0.3dB |
| v2.1 | -4.0dB | 2.3dB | 1.2dB | +1.1dB |

- `HrtfRenderer.timbreCurves`: 정면 쪽 방향(0°·±30°·±45°) 평균 응답을 1/3옥타브 평활 → 1kHz 위를 70% 펴는 곡선(모든 방향 공통이라
  두 귀 출력에 한 번에 곱함 = 방향끼리 차이는 그대로) + 남은 정면(0°) 굴곡을 가운데 스피커에만 더 펴는 곡선
- **v2.3: 세기를 고름 (`음색 보정` 0~100%, 기본 30%)** — 정면 귀 굴곡은 "필터 낀" 느낌의 원인이지만, 동시에 소리가
  **앞에서·머리 밖에서** 들리게 하는 단서라서 v2.1 처럼 다 펴면(100%) 앞 소리가 머리 안쪽으로 들어와 3D 느낌이 약해짐.
  곡선을 dB 로 세기만큼 곱해서 재생 중에 바로 바뀜 (0% = v2.0 과 같은 값, 100% = v2.1 과 같은 값으로 확인)

| Bose 보정 켬, 가운데(대사·노래) | 6~8kHz 골짜기 | 평균 굴곡 (정면 귀 단서 크기) |
|---|---|---|
| v2.0 (헤드폰 보정 100%) | -9.2dB | 5.2dB |
| 음색 보정 0% | -7.2dB | 4.2dB |
| **음색 보정 30% (기본)** | **-6.1dB** | **3.5dB** |
| 음색 보정 50% | -5.4dB | 3.1dB |
| 음색 보정 100% (= v2.1) | -4.0dB | 2.3dB |
- `HeadphoneEq.gentleGainDb`: 저음 깎기 35%, 300Hz 아래 깎기 50%, 1.5kHz 위 좁은(Q>2.5) 보정 30%
